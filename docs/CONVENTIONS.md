# Conventions

The why behind these rules is in `docs/PHILOSOPHY.md`.

## Folders

| Folder | Holds |
|---|---|
| `autoload/` | `Screens` (`ScreensService`): which surface shows which screen, swap, input routing |
| `core/dual_scene/` | `DualScene`, the base scene every screen inherits |
| `core/screens/` | Pieces `Screens` uses: presenter, second surfaces (desktop window, Android display) |
| `addons/dual_screen_android/` | Godot side of the Android plugin (export plugin + AAR) |
| `android/plugin/` | Kotlin source of the Android plugin |
| `data/schema/` | Resource scripts (the data contract) |
| `data/rules/` | Pure functions (dice, spaced repetition, brewing) |
| `data/demo/<kind>/` | Demo `.tres` content |
| `scenes/home/` | Launcher listing tools from `ToolEntry` data |
| `examples/<name>/` | Example tools, one self-contained folder each. Forks delete what they do not need |
| `ui/theme/`, `ui/components/` | Theme, reusable UI scenes (only after 3 real uses) |
| `assets/` | Fonts, art. Placeholder art is generated by `tools/` |
| `i18n/` | `strings.csv` (`keys,en,fr`) |
| `tests/` | `run_tests.gd`, `test_case.gd`, `test_*.gd` |
| `tools/` | Headless tool scripts |

## Code

- GDScript, full static typing (vars, params, returns, loop variables), `class_name` on every script.
- Typed arrays and dictionaries: `Array[HanziCard]`, `Dictionary[StringName, int]`.
- Autoload scripts use a `*Service` class name, the autoload name is the short one (`Screens`).
- Node references: `%UniqueName` with `@onready`, or `@export`. No long `get_node` paths.
- Signals up, calls down. Autoload signals only for cross-scene events.
- `##` doc comments on classes and public functions. Comments in English.

## Screens

- Sizes come from the device profile: `Screens.screen_size(screen)`. Do not hardcode 320x240; anchor UI to the
  viewport edges so a 412x360 or 640x360 screen also works.
- Text that must stay sharp at any size (hanzi, titles) uses an MSDF font and `texture_filter = LINEAR` on the node
  that draws it. Pixel fonts and pixel art stay nearest. A scene that needs the panel's full pixels sets
  `pixel_scale = 2`.
- Every screen scene inherits `core/dual_scene/dual_scene.tscn`. Top content goes under `%TopViewport`, bottom content
  under `%BottomViewport`.
- Set `top_redraw` / `bottom_redraw` to `ON_CHANGE` for screens that only change on input or data. Call
  `request_redraw(DualScene.Screen.TOP)` after changing them from code (tweens, timers).
- Change scenes only through `Screens.change_scene(path)`.
- Usually one screen holds the focusable controls. Keys and the gamepad reach both screens.

## Data

- `ContentData` style: shared fields in a base Resource, children add their own.
- Text in data is content (a hanzi, a meaning). UI labels are translation keys.
- Static content (`HanziCard`) is separate from runtime state (`CardProgress`).
- `.tres` for readable diffs.

## Input

Pointer input is **touch only**: handle `InputEventScreenTouch` / `InputEventScreenDrag`, never mouse events. The mouse
emulates touch on desktop (`input_devices/pointing/emulate_touch_from_mouse`). A viewport shown outside its container
has no hover, so mouse clicks would not reach it; touch always does.

Containers and labels drawn over a touch area set `mouse_filter = IGNORE` (2): by default a container catches the
touch and its siblings underneath never see it. Physics bodies picked up by a finger are steered with
`linear_velocity`, not frozen and moved (see DECISIONS).

Only InputMap actions, never raw keys: `ui_*` for menus, `swap_screens`, then one action per tool verb (`roll`,
`reveal`). Every action has a keyboard and a joypad event. Debug keys are letters, not F-keys.

## Translations

Every visible UI string is a key in `i18n/strings.csv`, read with `tr()` (or set as Label/Button text). Keys are
UPPER_SNAKE with a screen prefix (`HOME_`, `DICE_`, `HANZI_`, `BREW_`). Run `--import` after adding a key.

## Tests

- `tests/test_*.gd` extend `TestCase`. Methods `test_*`. `eq`, `ok`, `await frames()`, `await press(action)`.
- A test fails on any engine or script error logged while it runs, and after 15 s.
- Rules get unit tests. Each screen gets a smoke test driven through input actions.
- Tests run headless, so `Screens` uses the single (stacked) surface there.
